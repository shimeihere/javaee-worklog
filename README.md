# 企业日报周报与项目看板系统 (Worklog)

本项目为 JavaEE 期末大作业。系统名为 **周览 (Worklog)**，旨在解决企业内部日报/周报填报繁琐、数据汇总困难、项目进度不透明等痛点。系统采用前后端分离架构，实现了从“员工填报”到“主管审查”，再到“高管大盘”的完整业务闭环。

## 🛠️ 核心技术栈

*   **后端**：Java 17 / Spring Boot 3 / MyBatis-Plus / JWT (鉴权) / EasyExcel (数据导出)
*   **前端**：Vue 3 / Vite / Element Plus / Pinia / ECharts / Axios
*   **数据库**：MySQL 8.0

## 👥 四层角色与权限控制 (RBAC)

系统严格遵循企业管理学中的“最小特权原则”与“防越级审查”，实现了精准的数据范围隔离（DataScope）：

1.  **高管 (EXECUTIVE)**：全局视角。可查看全公司数据大盘与部门对比，拥有最高业务审查权限（下钻看明细），但不直接参与催报。
2.  **系统管理员 (ADMIN)**：系统基建维护者。负责账号、部门、项目管理，**无业务数据查看权限**（防内部泄密）。
3.  **部门负责人 (DEPT_LEADER)**：中层管理。只能查看本部门员工的大盘数据、日报明细，并拥有催报权限。
4.  **员工 (EMPLOYEE)**：执行层。只能进行自己的日报/周报填报与查看。

## 🚀 部署与运行指南

### 1. 环境准备
*   确保已安装 **JDK 17+**、**MySQL 8.0+**、**Node.js**。
*   在你的 MySQL 中创建一个名为 `worklog` 的数据库（`schema.sql` 里也会自动建）。

### 2. 数据库初始化
*   找到项目根目录下的 `schema.sql` 文件，直接导入 MySQL 执行（`mysql -uroot -p < schema.sql`）。
*   脚本会建库 `worklog`、建 9 张表，并写入演示数据：5 个部门、11 个账号、4 个项目、本周日报与周报。
*   演示数据里的日期用 `CURDATE()` 相对生成，任何时候导入都能看到"最近几天"的填报记录。

### 3. 配置数据库连接
把 `src/main/resources/application.example.yml` 复制成 `application.yml`（真实配置已被 `.gitignore` 排除，
不要提交到仓库），再把数据库账号密码改成你本地的配置：
```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/worklog_db?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai
    username: root        # 改为你的账号
    password: your_password # 改为你的密码

### 4. 启动
*   在项目根目录双击 `运行Worklog.bat`（自动用 `target\worklog.jar` 前台启动，端口 8080）；
*   或直接用 IDEA 运行 `WorklogApplication`；
*   浏览器访问 `http://localhost:8080/`，演示账号密码统一为 `123456`：
    `admin`（管理员）/ `liyue`（部门负责人）/ `wangfan`（员工）/ `boss`（高管）；
    另有 `yulan`（质量保障部负责人）、`chenjia`（质量保障部员工）。

## 🧩 数据模型（9 张表）

| 表 | 说明 |
|---|---|
| `sys_dept` | 两级部门树（`parent_id = 0` 为顶级） |
| `sys_user` | 账号、角色（EMPLOYEE / DEPT_LEADER / EXECUTIVE / ADMIN）、所属部门、启用状态 |
| `project` | 项目、负责人（`leader_id`）、所属部门、`planned_end_date` 计划完成日（空则只算已进行天数） |
| `project_member` | **项目成员关系**（管理员把用户加到项目后落在这张表） |
| `daily_report` | 日报，`user_id + report_date` 唯一 |
| `weekly_report` | 周报，`user_id + start_date` 唯一 |
| `attachment` | 附件（按 `report_type + report_id` 多态关联日报/周报） |
| `sys_message` | 站内信（催报提醒 + 系统通知） |
| `sys_audit_log` | 操作审计（谁在什么时候把谁的账号/部门/项目改成了什么，不含日报正文） |

> `project_member` 是"谁参与了这个项目"的权威来源；早期没有该表时只能靠"填过该项目的日报"反查，
> 现在两者取并集，历史数据不会因为补表而丢项目。

## 🆕 管理端增强（验收反馈对应）

1.  **单部门 / 单项目场景**：看板不再画"只有一个柱子的对比图"和"只有一个项目的排行榜"，
    改为大数字 + 横向进度条（如 `技术中心 14%`），不做没有比较对象的对比。
2.  **用户可编辑**：原来只能禁用/启用，现在可改姓名、角色、所属部门，并可直接把用户加入/移出项目；
    改动会写一条站内信通知本人，登录账号本身不可改。
3.  **批量新增用户**：支持把 Excel 里的「账号、姓名、角色、部门」直接粘贴进来，
    统一初始密码，逐行校验——成功的立即入库，失败的按行返回原因，不会因为一行重复就整批回滚。
4.  **汇总中心时间维度**：默认最近日期在前，打开就是今天/昨天，不用翻到最后一页。
5.  **权限约束**：编辑用户、批量新增仅管理员可用；不能修改自己的角色，也不能把系统里最后一个可用管理员降级。

## 🔁 第二轮反馈（甲方复核）

1.  **看板第 3 张卡不再重复**：首屏环图已经是"团队总提交率"，所以单部门时第 3 张卡换成
    **项目进度**（每个项目一条横向进度条：已提交份数 / 参与人数 / 进度%），多部门时才显示部门对比。
    项目口径按数据范围取**全部在管项目**，本期 0 份日报的项目也会以 0% 出现——项目看板要看得见"没人动"的项目；归档项目不再进入看板。
2.  **启用/禁用收进编辑**：用户列表不再单开"启用状态"列，姓名旁用「已禁用」标记；
    编辑弹窗里用开关改状态，仍然走原来的保护逻辑（不能禁用自己、不能禁用最后一个管理员、有草稿会提醒）。
3.  **项目可以编辑/归档**：项目列表新增「编辑」，可改名称、描述，可在「进行中 / 已归档」之间切换
    （归档不动历史日报与成员关系，只是退出看板与"进行中"视角）。
4.  **甲方视角核查后的修正**：
    * 待催报名单排除负责人本人（自己催自己没有意义）；
    * 日报/周报的「所属项目」改为**选填**——没被分配项目的员工原来交不了日报，这是硬阻塞；
    * 高管工作台的 "我的项目" 改为 "公司项目"（高管看到的是全公司项目数）。

## ⏱️ 第三轮反馈（项目周期 / 工作台 / 审计）

1.  **项目进度按"天数"说话**：project 新增 `planned_end_date`（计划完成日，选填）。
    看板里的项目进度条现在画的是**立项天数占比**（如"第 9 / 69 天 · 剩 60 天"），
    日报份数与提交率退到下方一行作为参考；没设计划完成日的项目显示"已进行 N 天"并画虚线空轨，
    超期则变驼色并显示"已超期 N 天"。项目列表、新建/编辑弹窗都带这一列/字段，归档项目不再进入看板。
2.  **工作台不堆卡片、也不留白**：下半区改成两列——左边「本周节奏 + 快捷入口」（7 个格子看本周哪天交了、
    哪天缺），右边「最近提交 / 最近操作 / 在管项目」（按角色切换）。管理员四个入口可直接落到
    系统设置的对应页签（`/system?tab=user|project|dept|audit`）。
3.  **操作审计**：新增 `sys_audit_log` 与「系统设置 → 审计日志」页签，记录新增/批量新增/编辑用户、
    启用禁用、部门新增编辑、项目新建/编辑/归档、变更负责人；只有管理员可见，可按动作与关键字筛选。

## 🎛️ 第四轮反馈（界面统一 / 弹簧交互）

1.  **三块面板同一套尺寸**：「本周节奏」「快捷入口」「最近动态」统一成同一套面板（同样的内边距、圆角、
    标题栏与右边距），不再出现一块长条面板旁边挂一墙小卡片的情况。
2.  **位置互换**：按"先看状态、再动手"的顺序，本周节奏在上、快捷入口在下。
3.  **格子数量跟着内容走**：
    * 快捷入口一行的格子数 = 入口数量（3 / 4 / 5 个），一行铺满；5 个入口时只保留标题（描述进 tooltip），
      不会再出现第 3 张卡片挤出右边界、或者"记录今天的…"这种截断；
    * KPI 的列数 = 指标数量（管理员 2 张、高管 3 张、员工 5 张、负责人 6 张），6 张也是一行，不会甩出孤儿卡；
      窗口小于 1200px 时自动降为 3 列（`240px` 保底），窄屏也不会挤成细条。
4.  **弹簧微交互**（统一用 `--wl-spring: cubic-bezier(.34,1.56,.64,1)` 的过冲曲线）：
   面板入场做位移 + 轻微缩放回弹；KPI 卡片、快捷入口、节奏格子、最近动态在 hover 时上浮/右移、
    图标与圆点同步放大，`:active` 回缩；`prefers-reduced-motion: reduce` 时整套动效关闭。
5.  **演示数据补齐**：负责人（李悦）与员工（王帆）本周的日报，以及新部门「质量保障部」的两个账号
